# auth — `/auth`

## 使用者任務

用帳號密碼登入，或 30 秒內註冊一個帳號，然後回到原本要做的事（`next`）。要清楚知道：不登入也能查課、註冊只需帳號與密碼、帳號名之後不能改。

## 可用資料

- `POST /api/auth/login{username, password}`、`POST /api/auth/register{username, password, displayName?}` → `Me` + `uc_session` cookie。
- 錯誤訊息對照在 `apps/web/src/lib/community-messages.ts`（帳密錯誤、嘗試過多、帳號已用、格式）。
- `next` 參數決定成功後去向。

## 借用的家族模式

| 元素 | 借自 | 為什麼 |
| --- | --- | --- |
| 單張置中卡、segmented tabs | site `/login`、yt 登入頁 | 家族登入頁都是最小化卡片 |
| 一句「為什麼要登入」 | tag 登入頁的說明 | 降低不必要註冊 |
| 欄位提示放在 label 同列右側 13 px muted | puma 表單 | 現在提示在欄位下方會把表單拉長 |
| 「登入後會回到：…」 | tag `next` 顯示 | 讓 `next` 可見，減少迷路 |

## 要加的圖表

無（viz = null）。

## 互動

- 密碼「顯示」切換（JS；無 JS 隱藏）。
- 錯誤後保留帳號欄（現有）。
- 註冊成功直接登入並導向 `next`。
- Tabs 是連結（無 JS 可用），`aria-current="page"`。

## 狀態

- 登入失敗／嘗試過多：alert 區塊（現有文案）。
- 已登入造訪 `/auth`：導向 `next` 或顯示「你已登入為 @id」+ 登出。
- API 失敗：alert「暫時無法完成，請稍後再試」。

## 驗收標準

- task：兩個欄位 + 一顆按鈕；手機第一屏看得到按鈕。
- hierarchy：標題 → 說明 → tabs → 欄位 → 按鈕 → 替代連結。
- density：卡內 gap 12 px；欄位 44 px。
- family：卡片、tabs、按鈕 token 一致；深色卡 `--panel`。
- type：h1 20 px；提示 12–13 px。
- mobile：卡片無邊距重複（手機不畫卡框，直接貼頁面）。
- a11y：`autocomplete` 正確；錯誤 `role="alert"`、欄位 `aria-invalid`、`aria-describedby` 提示。
- states：失敗、過多、已登入、API 失敗。
- copy：「帳號」「密碼」「顯示名稱」「建立帳號」一致。
- feel：送出時按鈕 pending、避免雙送。

## 本頁最大的改變

提示移到 label 同列、加上「查課不用登入」與「登入後會回到」兩句，讓頁面更短更明確。
